Technology Overview

Understanding what each technology does and how they work together:

Full-Stack Development

What it is: Building both the frontend (what users see) and backend (server, database, logic).

Why it matters: You can build complete applications from UI to database, making you versatile and valuable.

Example: Building an e-commerce site - you handle the product display, shopping cart, payment processing, and order management.

React

What it is: A JavaScript library for building user interfaces using reusable components.

Why it matters: Most popular frontend library. Used by Facebook, Instagram, Netflix, Airbnb.

Key concept: Build UI from small pieces (components) like LEGO blocks. Each piece manages its own state and can be reused.

Next.js

What it is: A React framework that adds server-side rendering, routing, and API capabilities.

Why it matters: Better SEO, faster page loads, easier deployment. The standard for modern React apps.

Key concept: React on steroids - handles routing, data fetching, and server logic automatically.

TypeScript

What it is: JavaScript with type safety. Catches errors before code runs.

Why it matters: Prevents bugs, improves code quality, makes large projects manageable.

Key concept: Define what type of data each variable holds (string, number, object) - TypeScript enforces it.

How they work together: React builds the UI → TypeScript makes it type-safe → Next.js adds routing, SSR, and backend capabilities → Result: Production-ready full-stack application.

Quick Reference Cheat Sheets

React Hooks Cheat Sheet

useState(initialValue) // Manage component state
const [count, setCount] = useState(0)
useEffect(() => {}, [deps]) // Run side effects (API calls, subscriptions)
useEffect(() => { fetchData() }, [])
useContext(MyContext) // Access context values
const user = useContext(UserContext)
useRef(initialValue) // Persist values across renders, DOM access
const inputRef = useRef(null)
useMemo(() => computation, [deps]) // Memoize expensive calculations
const total = useMemo(() => items.reduce(...), [items])

TypeScript Types Cheat Sheet

string, number, boolean // Basic types
let name: string = "Mike"
Type[] or Array<Type> // Arrays
let numbers: number[] = [1, 2, 3]
interface / type // Object shapes
interface User { name: string; age: number }
Type | OtherType // Union types (can be either)
let id: string | number
Type? // Optional properties
interface User { email?: string }
<T> // Generics
function identity<T>(arg: T): T { return arg }

Next.js Patterns Cheat Sheet

pages/index.tsx // Home page (route: /)
pages/about.tsx // About page (route: /about)
pages/blog/[slug].tsx // Dynamic route (route: /blog/my-post)
pages/api/hello.ts // API endpoint (route: /api/hello)
getStaticProps() // Fetch data at build time (SSG)
export async function getStaticProps() { return { props: {} } }
getServerSideProps() // Fetch data on each request (SSR)
export async function getServerSideProps() { return { props: {} } }
import Link from 'next/link' // Client-side navigation
<Link href="/about">About</Link>

Common Interview Questions

Q: What is the virtual DOM?
A: Lightweight copy of actual DOM. React compares it with real DOM and only updates what changed (efficient).
Q: What's the difference between SSR and SSG?
A: SSR generates HTML on each request (dynamic). SSG generates HTML at build time (static, faster).
Q: Why use TypeScript over JavaScript?
A: Catches errors before runtime, better IDE support, easier to refactor large codebases, self-documenting code.
Q: What are React hooks?
A: Functions that let you use state and lifecycle features in functional components (useState, useEffect, etc.).
Q: When would you use Next.js over plain React?
A: When you need SEO, server-side rendering, file-based routing, API routes, or built-in optimization.
